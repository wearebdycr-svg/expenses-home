# PLAN 01-01: Aislamiento de Estado Cron en `cron_executions`, Suite de Tests y Gates en CI

## Objetivo
Mover el registro de deduplicación de crons fuera de `category_budgets` hacia una tabla dedicada `public.cron_executions` en Supabase, actualizar `api/cron-reminder.js`, crear una suite unitaria completa con mocks para `api/cron-reminder.js` y añadir los gates de `tsc --noEmit` y `node --test api/*.test.mjs` en el pipeline de GitHub Actions.

---

## Tareas Específicas

### Tarea 1: Crear script DDL para `public.cron_executions` y limpieza de sentinelas (`REQ-CRON-01`)
- **Archivo a crear:** `supabase/cron_executions_schema.sql`
- **Acción:**
  - Definir la tabla `public.cron_executions` con `job_name TEXT PRIMARY KEY`, `last_run_date NUMERIC NOT NULL` (`YYYYMMDD`), `last_run_at TIMESTAMPTZ DEFAULT now() NOT NULL`, `metadata JSONB DEFAULT '{}'::jsonb`, `updated_at TIMESTAMPTZ DEFAULT now() NOT NULL`.
  - Habilitar RLS y revocar permisos directos a `anon`.
  - Crear políticas de lectura, inserción y actualización para `authenticated`.
  - Añadir sentencia de limpieza idempotente: `DELETE FROM public.category_budgets WHERE category LIKE '__cron_%';`.

### Tarea 2: Refactorizar `api/cron-reminder.js` para usar `cron_executions` (`REQ-CRON-01`)
- **Archivo a modificar:** `api/cron-reminder.js`
- **Acción:**
  - En la sección de deduplicación de gastos fijos (líneas ~412–426), reemplazar la consulta a `category_budgets` (`category = '__cron_fixed_expenses__'`) por consulta a `cron_executions` (`job_name = 'fixed_expenses'`), leyendo `last_run_date`.
  - En la sección de persistencia de deduplicación de gastos fijos (líneas ~546–555), hacer `upsert` en `cron_executions` con `job_name: 'fixed_expenses'`, `last_run_date: todayColombiaNum`, `last_run_at: new Date().toISOString()`, `metadata: { deliveredAlerts, evaluated, isoDate: todayColombiaIso }`, `updated_at: new Date().toISOString()`.
  - En la sección de deduplicación del recordatorio diario (líneas ~578–595), reemplazar la consulta a `category_budgets` (`category = '__cron_reminder_7pm__'`) por consulta a `cron_executions` (`job_name = 'daily_reminder_7pm'`).
  - En la persistencia del recordatorio diario (líneas ~643–654), hacer `upsert` en `cron_executions` con `job_name: 'daily_reminder_7pm'`, `last_run_date: todayColombiaNum`, `last_run_at: new Date().toISOString()`, `metadata: { deliveredCount: sent, isoDate: todayColombiaIso }`, `updated_at: new Date().toISOString()`.
  - Asegurar que ambas operaciones estén envueltas en `try/catch` con `console.warn` defensivo para no bloquear la ejecución si la tabla estuviera ausente o en mantenimiento.

### Tarea 3: Implementar suite de pruebas unitarias `api/cron-reminder.test.mjs` (`REQ-TEST-01`)
- **Archivo a crear:** `api/cron-reminder.test.mjs`
- **Acción:**
  - Utilizar el runner nativo de Node (`import { describe, it, beforeEach, afterEach } from 'node:test'`, `import assert from 'node:assert/strict'`).
  - Probar los escenarios principales:
    1. Salto de ejecución cuando `cron_executions` ya tiene registrado el día actual (`last_run_date === todayColombiaNum`).
    2. Ejecución forzada (`force = true` o `force=1`) ignorando deduplicación y ventana horaria (18:45–20:15 Colombia).
    3. Omisión del recordatorio de 7 PM si ya existen gastos registrados en la fecha de hoy.
    4. Filtrado por tipo de cron (`cronType === 'fixed_expenses'` vs `cronType === 'daily_reminder'` vs `cronType === 'all'`).
    5. Manejo tolerante a fallos cuando la consulta a Supabase falla o no hay tokens disponibles.
  - Asegurar ejecución 100 % offline con mocks en memoria para `fetch` y el cliente Supabase, sin tocar servicios de red externos.
  - Nota de implementación: contemplar la guarda horaria Colombia (18:45–20:15) en `api/cron-reminder.js` usando `force=true` o simulando el reloj según corresponda para que la deduplicación sea testeable de forma determinista.

### Tarea 4: Actualizar CI y scripts en `package.json` (`REQ-CI-01`)
- **Archivos a modificar:** `.github/workflows/tests.yml`, `package.json`
- **Acción:**
  - En `package.json`, añadir los scripts:
    - `"test:api": "node --test api/*.test.mjs"`
    - `"typecheck": "tsc --noEmit"`
  - En `.github/workflows/tests.yml`:
    - Añadir paso `name: TypeScript Type Check` con `run: npx tsc --noEmit` inmediatamente *después* de `Generate Environment Config` (`npm run config:env`) para disponer de `src/environments/environment.ts`.
    - Añadir paso `name: Run Serverless Node Tests` con `run: node --test api/*.test.mjs`.
